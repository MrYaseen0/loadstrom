1 · Target

Paste the address of a site or server you own. http and https are supported.

2 · Load profile

Concurrent users = how many virtual users hit the site at once. Target rate 0 = go as fast as those users can. Duration 0 = unlimited (runs until you click Stop). Capped at 10,000 per run — one machine can't usefully drive more (ports/sockets run out); scale with Stress mode or extra generators.
Stress mode climbs user count step by step until the site fails your rules — that level is your breaking point.

3 · Pass / fail rules

Advanced · headers, body, TLS, redirects, HTTP/2, precision
Set max redirects to 0 to disable redirect following.
If the error rate blows past this level, Strom Fire stops the test by itself instead of hammering a failing server. 0 disables the valve.
HTTP/2 requires HTTPS target. Precise pacing uses busy-wait for sub-millisecond accuracy (higher CPU). Phase tracking adds per-request DNS/TCP/TLS/TTFB breakdown.
Anonymity & Proxy · hide identity, rotate fingerprints
HTTP/HTTPS proxy (CONNECT) or SOCKS5. For Tor: socks5://127.0.0.1:9050. Leave empty for direct connection. List enables round-robin rotation per virtual user.
Auto-rotate is on but no proxy is set — rotation only acts with a Proxy URL or Proxy List; otherwise it does nothing.
Proxy hides your real IP. Header profiles mimic real browsers. Cookie isolation = each virtual user has own session. Session simulation = realistic think time. Jitter = random delay per request. Proxy list = round-robin IP rotation. Combine with Tor for full anonymity.
Auto-rotate: When blocked (high timeout rate), Strom Fire automatically switches to a new Tor circuit or next proxy in list. Tor control port defaults to 9151 (Tor Browser). Block threshold = % of errors that triggers rotation.
Presets · quick config
Gentle = 10 users, safe thresholds. Normal = 50 users. Aggressive = 200 users, tight timeouts. Stress = ramp mode, find breaking point.
